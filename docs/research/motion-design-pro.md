# Профессиональный моушн для коротких обучающих роликов — руководство для библиотеки пресетов

Канал kemel-bilim. Серия 1 — английский (зрители говорят по-русски и по-казахски, 7–16 лет), потом математика.
Формат: 60–90 с, 9:16 (1080×1920) и 16:9 (1920×1080), игровые вставки (квиз, таймер, раскрытие, звёзды), без липсинка, картинки от fal.ai.
Цель документа — дать числа, которые можно положить в JSON-пресеты и применять из ExtendScript.

Условные обозначения: **f30 / f60** — кадры при 30 и 60 fps. Все длительности даны в мс и в кадрах; при 60 fps кадров вдвое больше, время то же.
Пометка **[И]** — число взято из источника; **[П]** — отраслевая практика или вывод автора (проверять глазом на своём материале).

---

## 0. Главные правила

1. **Один кадр — одна мысль.** На экране в каждый момент один главный объект и максимум 2 вспомогательных. Если новый элемент не нужен для текущей фразы диктора, его нет на экране (Mayer, coherence).
2. **Движение работает на смысл.** Каждая анимация отвечает на вопрос «куда смотреть» или «что поменялось». Декоративное движение — только фон и idle, и с амплитудой ниже 2–3 % кадра.
3. **Входы с замедлением в конце (ease-out), выходы с ускорением (ease-in), перемещения внутри кадра — ease-in-out.** Линейная интерполяция только для вращения по кругу, скролла паттернов и таймеров.
4. **Выход на 25–35 % короче входа.** Анимацию, которая выходит, не разглядывают.
5. **Визуал меняется каждые 2–4 с** (смена кадра, новый элемент, зум или подсветка). Статичный кадр дольше 5–6 с без нового стимула — провал удержания в Shorts [П].
6. **Текст держится на экране, пока его успевает прочитать ребёнок, для которого английский — второй язык:** базово 1,0 с + 0,35 с на слово (подробно в §1.4).
7. **Паузы голоса — это места для движения.** Ключевая анимация начинается за 2–4 кадра (f30) до ударного слова, а не после него.
8. **Палитра серии — 1 фон, 1 тёмный текстовый, 1 светлый, 1 акцент, 2 семантических (верно/неверно) и не больше 2 вспомогательных.** Акцент занимает не больше 10 % площади кадра.

## 1. Тайминг и ритм

### 1.1 Базовые длительности

Ориентиры из UI-моушна (Material: 50–500 мс шагом 50 мс [И]; NN/g: ~100 мс для микрообратной связи, 200–300 мс для крупных смен экрана [И]) для видео растягиваются в 1,3–2 раза: в видео зритель не взаимодействует, ему нужно успеть увидеть движение. Kurzgesagt анимирует в 60 fps [И] — для плавных медленных движений и параллакса это заметно лучше.

| Действие | мс | f30 | f60 | Кривая |
|---|---|---|---|---|
| Микро-реакция: «тык», пульс, моргание акцента | 150–250 | 5–8 | 9–15 | ease-out / back-out |
| Появление иконки, стикера, бейджа | 300–450 | 9–14 | 18–27 | back-out (overshoot 5–12 %) |
| Появление текстового блока (строка) | 400–600 | 12–18 | 24–36 | expo-out / quint-out |
| Слово в покадровой типографике | 250–400 на слово | 8–12 | 15–24 | quint-out |
| Буква в «печатной» анимации | 1–2 кадра на букву | 1–2 | 2–4 | hold / ease-out 4f |
| Крупный объект / картинка влетает | 500–800 | 15–24 | 30–48 | expo-out |
| Перемещение объекта внутри кадра (A→B) | 500–900 | 15–27 | 30–54 | ease-in-out (cubic/quart) |
| Выход элемента | 200–400 | 6–12 | 12–24 | ease-in (cubic/quart) |
| Переход между сценами (wipe, zoom, shape) | 400–700 | 12–21 | 24–42 | expo-in-out |
| Whip pan / быстрый смаз | 250–400 | 8–12 | 15–24 | expo-in-out + motion blur |
| Прорисовка линии/стрелки (trim path) | 300–700 | 9–21 | 18–42 | quart-out / expo-out |
| Подчёркивание слова | 250–400 | 8–12 | 15–24 | expo-out |
| Обводка-круг вокруг детали | 400–600 | 12–18 | 24–36 | quart-in-out |
| Медленный Ken Burns на картинке | вся сцена 3–8 с | — | — | linear или sine-in-out |
| Трансформация формулы (morph) | 700–1200 | 21–36 | 42–72 | smooth (≈ cubic-in-out) |
| Раскрытие ответа (flip, burst) | 400–600 + 300 settle | 12–18 + 9 | 24–36 + 18 | back-out |
| Вылет звезды/очков к счётчику | 500–700 | 15–21 | 30–42 | ease-in по пути + scale bump |

**Правило дистанции [П]:** чем больше путь, тем дольше движение, но не пропорционально. Рабочая формула: `t = 300 мс + 0,25 мс × путь_в_px` (для 1080 px по ширине: путь 200 px ≈ 350 мс, 1000 px ≈ 550 мс), потолок 900 мс.

**Правило масштаба [П]:** появления через scale начинаются не с 0 %, а с 60–85 % (иначе «вылупление из точки» выглядит дёшево), в паре с opacity 0→100 за первые 40–60 % длительности. Исключение — стикер с overshoot: 0 → 110 → 97 → 100 %.

### 1.2 Кривые easing: значения bezier и перевод в AE

В AE нет cubic-bezier напрямую, но любую CSS-кривую `cubic-bezier(x1,y1,x2,y2)` для одномерного сегмента между двумя ключами можно перевести в **influence** и **speed**:

- выходной ключ 1: `influence_out = x1 × 100 %`, `speed_out = (y1 / x1) × v_avg`;
- входной ключ 2: `influence_in = (1 − x2) × 100 %`, `speed_in = ((1 − y2) / (1 − x2)) × v_avg`;
- `v_avg = |value2 − value1| / (t2 − t1)` (единицы в секунду). Если `x1 = 0`, speed берётся как очень большое, практически ставят influence 0,1 %.
- Для spatial-свойств (Position 2D/3D) speed считается по длине пути. Надёжнее делать **Separate Dimensions** и анимировать X/Y раздельно — тогда кривые точные.
- В ExtendScript: `prop.setTemporalEaseAtKey(k, [new KeyframeEase(speedIn, inflIn)], [new KeyframeEase(speedOut, inflOut)])`; для многомерных несеперированных свойств массив из 1 элемента (spatial) или по одному на измерение (Scale, Anchor Point — 3 штуки).
- Influence в AE ограничен 0,1–100 %. Overshoot (y > 1 или y < 0) одним сегментом AE сделать не может: speed не бывает отрицательной. Overshoot = **дополнительный ключ** (0 → 108 % → 100 %) или выражение (inertial bounce).

| Имя пресета | cubic-bezier | Ключ 1 (out) | Ключ 2 (in) | Где |
|---|---|---|---|---|
| `linear` | 0,0,1,1 | — | — | вращение, скролл, таймер |
| `easyEase` (AE по умолчанию) | ≈0.33,0,0.67,1 | infl 33,3 %, speed 0 | infl 33,3 %, speed 0 | только черновик; выглядит «по умолчанию» |
| `sineInOut` | 0.37,0,0.63,1 | 37 %, 0 | 37 %, 0 | дыхание, idle, Ken Burns |
| `cubicInOut` / M3 standard | 0.65,0,0.35,1 / 0.2,0,0,1 | 65 %, 0 | 65 %, 0 | перемещение A→B |
| `quartInOut` | 0.76,0,0.24,1 | 76 %, 0 | 76 %, 0 | «кинематографичное» A→B, морфинг |
| `expoInOut` | 0.87,0,0.13,1 | 87 %, 0 | 87 %, 0 | переходы между сценами, whip |
| `quintOut` | 0.22,1,0.36,1 | 22 %, speed 4,5×v | 64 %, 0 | текст, иконки |
| `expoOut` (главная кривая «дорогого» моушна) | 0.16,1,0.3,1 | 16 %, speed 6,25×v | 70 %, 0 | входы, влёт, раскрытие |
| M3 emphasized decelerate | 0.05,0.7,0.1,1 [И] | 5 %, speed 14×v | 90 %, 0 | очень резкий старт, мягкая посадка |
| `cubicIn` / M3 accelerate | 0.32,0,0.67,0 / 0.3,0,1,1 [И] | 32 %, 0 | 33 %, speed 3×v | выходы |
| `expoIn` | 0.7,0,0.84,0 | 70 %, 0 | 16 %, speed 6,25×v | выход перед переходом |
| `backOut` (overshoot) | 0.34,1.56,0.64,1 | AE: 3 ключа | — | стикеры, бейджи, звёзды |

**Упрощённое правило для AE без вычислений [П]:** ease-out «по-взрослому» — первый ключ linear (или influence 10–20 %), второй ключ speed 0, **influence 75–90 %**. Ease-in-out — оба ключа speed 0, influence 60–85 %. Значение 33 % (Easy Ease) — главный признак непрофессиональной анимации: движение выглядит вялым посередине и тупым на концах.

**Overshoot (back-out) ключами [П]:**

| Свойство | Ключи (в долях длительности) | Значения |
|---|---|---|
| Scale стикера | 0 → 0,55 → 0,8 → 1,0 | 0 % → 112 % → 96 % → 100 % (ease-out на каждом, influence 60 %) |
| Position влёт | 0 → 0,65 → 1,0 | старт → 104 % пути → 100 % |
| Rotation «пружина» | 0 → 0,5 → 0,8 → 1,0 | −8° → +4° → −1,5° → 0° |

Overshoot выражением (на свойство с ≥2 ключами): `amp = 0.06; freq = 2.5; decay = 6;` — классический inertial bounce (amp 0,04–0,08 для текста, 0,08–0,15 для стикеров; freq 2–3; decay 5–8). Для текста overshoot — максимум 3–5 %, иначе текст «прыгает» и мешает читать.

### 1.3 Stagger (каскад)

| Что каскадируется | Задержка между элементами (f30) | мс | Порядок |
|---|---|---|---|
| Буквы (заголовок до 12 символов) | 1–2 | 33–66 | слева направо |
| Слова в строке | 2–4 | 66–133 | по порядку чтения |
| Строки абзаца | 4–6 | 133–200 | сверху вниз |
| Карточки/варианты ответа (2–4 шт.) | 3–5 | 100–166 | по порядку A, B, C, D |
| Иконки в сетке | 2–3 | 66–100 | от центра или по диагонали |
| Элементы инфографики (столбики) | 3–4 | 100–133 | слева направо |

**Правило суммарного каскада [П]:** весь каскад одного блока ≤ 600–800 мс. Если элементов много, задержку уменьшают, а не удлиняют общий вход. Задержки с лёгкой нелинейностью (каждая следующая на 10–15 % короче) выглядят естественнее равных.

### 1.4 Удержание текста (время на прочтение)

Данные:
- Netflix: лимит скорости субтитров 20 символов/с для взрослых, **17 символов/с для детских программ** (английский) [И]; для немецкого 17/13 [И]; минимум показа 5/6 с (25 кадров при 29,97 fps), максимум 7 с [И]; между сменами субтитров минимум 2 кадра [И].
- Для детей рекомендуют ~13 символов/с и ниже [И].

Наши зрители читают на неродном языке, значит ориентир ниже детского Netflix.

| Тип текста | Формула удержания | Пример |
|---|---|---|
| Новое английское слово (крупно) | ≥ 2,5 с, плюс время, пока диктор произносит его дважды | «apple» — 3 с |
| Перевод (RU/KZ) под словом | ≥ 1,5 с после появления | 1,5–2 с |
| Строка на английском (L2) | `1,0 с + 0,4 с × слов` (≈ 10–12 символов/с) | 6 слов → 3,4 с |
| Строка на родном языке | `0,8 с + 0,3 с × слов` (≈ 13–15 символов/с) | 6 слов → 2,6 с |
| Вопрос квиза | время озвучки + 1,0 с | — |
| Формула/пример (математика) | 2 с + 0,5 с на каждый новый символ операции | «3 + 4 = 7» → ~3,5 с |
| Минимум для любого текста | 0,9 с (27 кадров f30) | — |
| Максимум текста без изменений | 6–7 с, потом подсветка или смена | — |

Правило синхронизации: текст, повторяющий речь, появляется **одновременно** со словом (±3 кадра), не раньше чем за 6 кадров. Текст, который зритель должен прочитать сам (вопрос, задача), — за 0,3–0,5 с до озвучки.

### 1.5 Частота смены визуала

- Гуо, Ким, Рубин (6,9 млн просмотров edX) — вовлечённость резко падает у роликов длиннее 6 минут; рисованные «как у Khan» туториалы вовлекают сильнее слайдов [И]. Для 60–90 с это значит: ролик = 3–5 смысловых сегментов по 12–25 с.
- Для Shorts: первые 2–3 секунды решают, останется ли зритель [И]; начинать с самого насыщенного кадра, без «привет» и логотипа [И]; списочный формат («3 слова, которые…») держит удержание ровным, потому что каждый пункт — отдельная мини-развязка [И].

| Уровень | Интервал [П] |
|---|---|
| Новый визуальный стимул (элемент, подсветка, зум, смена позы героя) | каждые 2–4 с |
| Смена сцены/фона/плана | каждые 6–12 с |
| Смысловой сегмент (новое слово, новое правило) | каждые 12–25 с |
| Игровое взаимодействие (вопрос, «повтори», таймер) | каждые 20–30 с; в 60–90 с ролике 2–3 вставки |
| Хук | 0–3 с: вопрос или неожиданная картинка, без логотипа |
| Финал | последние 5–8 с: итог + звёзды + CTA, логотип ≤ 1,5 с |

Пример структуры на 75 с: хук (0–3) → тема (3–8) → 3 блока по ~15 с (слово/правило + пример + микроповтор) → квиз с таймером (≈ 12 с) → итог и награда (6 с).

### 1.6 Работа с голосом, битом и паузами

- **Предупреждение (anticipation):** главное движение стартует за 2–4 кадра (f30) до ударного слога; тогда остановка движения совпадает со словом (звук на 60–100 мс «поздно» мозг прощает, видео позже звука — нет).
- **Паузы в VO:** после нового понятия в озвучке нужна пауза 0,6–1,2 с — в неё ставится визуальный акцент (подсветка, подчёркивание). После вопроса «подумай» — пауза под таймер (§4).
- **Музыка:** 90–110 BPM для детского обучения [П]. Бит при 100 BPM = 0,6 с = 18 кадров f30. Сцены режутся на сильную долю, мелкие появления — на каждую четверть или восьмую (9 кадров). Музыка под голосом −18…−24 LUFS относительно VO (VO ≈ −14…−16 LUFS integrated для YouTube), ducking −6…−10 дБ на время речи.
- **SFX:** у каждого типа движения свой звук из короткого набора (pop — появление, whoosh — переход, tick — таймер, ding — верно, buzz/soft thud — неверно, sparkle — звезда). Громкость SFX на 6–10 дБ ниже голоса. Звук ставится на кадр «касания» (конец движения или пик overshoot), whoosh — с началом.
- **Accent rhythm:** не больше одного «громкого» события (overshoot + SFX + camera shake) на 4–6 с, иначе всё становится одинаково громким и сигнал теряется.

## 2. Донесение информации

### 2.1 Принципы Mayer → правила моушна

| Принцип | Суть [И] | Правило для пресетов |
|---|---|---|
| Coherence | убирать лишнее | фон слабее объекта (§3а), не больше 3 активных элементов; без декоративного текста |
| Signaling | подсказки, что важно (стрелки, выноски, подсветка) | пресеты highlight/underline/circle/arrow, затемнение остального до 40–60 %; мета-анализ Schneider и др. 2018: g = 0,53 для запоминания, 0,33 для переноса [И] |
| Redundancy | графика + голос лучше, чем графика + голос + тот же текст полностью | на экране **ключевые слова**, а не транскрипт речи. Исключение для языка: целевое слово и пример **должны** быть текстом (это и есть учебный материал) |
| Spatial contiguity | связанный текст и картинка рядом | подпись ≤ 40–80 px от объекта или коннектор; никаких легенд «в углу» |
| Temporal contiguity | слово и картинка одновременно | появление объекта синхронно со словом (±3 кадра) |
| Segmenting | порции, ритм задаёт ученик | сегменты 12–25 с с явной «точкой» (звук, смена фона); в видео ритм ученика заменяют пауза и «нажми паузу, если нужно» |
| Pre-training | сначала названия и свойства | перед сложной сценой — карточка-словарик 2–3 слова; в математике — назвать части («это числитель») до операции |
| Modality | объяснять картинку голосом, а не подписью | длинные пояснения — в VO, на экране только термины |
| Multimedia | слова + картинки лучше, чем только слова | каждое новое слово — с картинкой |
| Personalization / Voice | разговорный стиль, человеческий голос | «ты», вопросы к зрителю; живой голос или хороший TTS |
| Embodiment | экранный персонаж с жестами | герой-гид показывает (pointing), смотрит на объект; взгляд героя — сигнал |

### 2.2 Иерархия и фокус

- **3 уровня важности максимум:** главный объект (100 % насыщенность, крупный, по центру или в золотой точке) → поддержка (60–80 %) → фон (≤ 30–40 % контраста относительно главного).
- **Фокус-приёмы (от слабого к сильному):** смена цвета → увеличение 105–115 % → подчёркивание → обводка → затемнение остального (dim до 35–50 % opacity или black overlay 40–60 %) → зум камеры к объекту 120–200 % → изоляция (spotlight с размытой маской, feather 80–200 px).
- **Глаз ведётся движением:** новое движение в кадре всегда «перебивает» неподвижное. Поэтому в момент, когда важен объект A, всё остальное неподвижно (idle с амплитудой ≤ 2 px и периодом ≥ 2 с допустимо).
- **Порядок чтения:** слева направо, сверху вниз; входы направлены туда же (новое приходит справа или снизу, старое уходит влево или вверх). Для серии: «вперёд по уроку» = справа налево (движение влево), «назад/повтор» = вправо.
- **Прогрессивное раскрытие:** список/формула/диаграмма строится по одному элементу на фразу; уже объяснённые элементы приглушаются до 50–60 %, новый — 100 % + акцент.

### 2.3 Специфика: обучение английскому

Структура подачи слова (карточка слова), 6–10 с:

| Шаг | Время | Визуал | Голос |
|---|---|---|---|
| 1. Картинка (смысл) | 0,0 | картинка влетает (expo-out 18f) | — / звук-подсказка |
| 2. Слово | +0,4 с | слово крупно, stagger по буквам 1f | диктор произносит слово |
| 3. Произношение | +1,2 с | транскрипция /ˈæp.əl/ мельче (55–60 % размера слова), ударный слог подсвечен | слово медленно, по слогам; затем нормально |
| 4. Перевод | +2,5 с | перевод RU/KZ ещё мельче (45–50 %), нейтральный цвет | перевод |
| 5. Пример в контексте | +4 с | фраза, целевое слово выделено акцентом/подчёркнуто; картинка сцены | фраза |
| 6. Повторение | +6 с | «Repeat!» + пауза 1,5–2 с с индикатором (пульсирующий микрофон/волна) | пауза для зрителя |

Правила:
- **Единый цветовой код частей речи / ролей во всей серии** (пример: существительное — синий, глагол — оранжевый, прилагательное — зелёный). Код вводится один раз (pre-training) и не меняется между эпизодами.
- **Транскрипция:** шрифт с полной поддержкой IPA (Noto Sans, Charis SIL, Doulos SIL, Gentium) — проверять «ə ɪ ʊ θ ð ŋ ʃ ʒ ˈ ˌ». Ударение — цвет или точка над слогом, а не только «ˈ». Для младших возможна кириллическая подсказка (э́пл), но в отдельном стиле (курсив/серый), чтобы не путать с орфографией.
- **Слогоделение и звуки:** слог/буквосочетание подсвечивается синхронно со звуком (время подсветки = длительность слога ±2 кадра).
- **Повторение (retrieval):** через 20–40 с в ролике слово возвращается уже **без перевода** — «как это по-английски?», пауза, раскрытие. Активное припоминание эффективнее повторения за диктором (Kang, Gollan, Pashler 2013) [И]. В конце ролика — повтор всех слов сеткой 2×2/3×2 со stagger 4f.
- **Минимальные пары и сравнение:** split-screen 50/50, разделитель 4–6 px, обе половины одинаково яркие, отличие подсвечено.
- **Трёхъязычие:** английский — главный (100 %, жирный), перевод — вторичный (60–70 % яркости, regular). Не выводить RU и KZ одновременно больше чем на 2 с в 9:16 — выбрать один язык на версию ролика или показать их последовательно.

### 2.4 Специфика: математика (подход 3Blue1Brown/Manim)

Manim по умолчанию: `run_time = 1 с`, `rate_func = smooth` (S-кривая, ≈ cubic-in-out) [И]; на практике для трансформаций формул ставят 2–3 с [И].

| Приём | Параметры |
|---|---|
| Трансформация формулы (TransformMatchingTex) | одинаковые части формулы остаются на месте/плавно переезжают (700–1200 мс, smooth); исчезающие — fade 300 мс; новые — fade+scale от 80 % за 400 мс, начинаются на 30–40 % позже. Реализация в AE: каждый токен формулы — отдельный текстовый слой с id; переезд по id |
| Подсветка части формулы | цвет токена → акцент за 6–8f; или плашка за токеном (радиус 8–12 px, padding 6–10 px, 25–35 % opacity акцента); или обводка/подчёркивание; остальное — 50–60 % |
| Цветовое кодирование переменных | одна переменная = один цвет во всей сцене и в тексте VO-подписей (3B1B: x — жёлтый, y — синий и т. д.) |
| Числовая прямая | линия 4–6 px (1080p), риски 2–3 px длиной 16–24 px, подписи под рисками 28–36 px; прорисовка линии 500 мс expo-out, риски stagger 1–2f; «прыжки» — дуги trim path 400–600 мс, точка-маркер 16–24 px; зум к участку — scale камеры 300–400 % за 1–1,5 с quart-in-out |
| Графики | оси появляются первыми (trim 400 мс), сетка 15–20 % opacity, кривая рисуется trim path 1–2 с linear или sine-in-out (чтобы «ручка» шла равномерно), точка-«бегунок» на конце |
| Перенос/группировка | объекты перемещаются по дуге (не по прямой) — 15–25 % от длины пути выгиб |
| «Подсчёт» | счётчик чисел — linear по значению или ease-out, целые числа, табличные цифры (tabular figures), иначе текст дрожит |
| Дроби/части | круг/полоса делится линиями trim 300 мс, доли заливаются по очереди stagger 4–6f |
| Пауза осмысления | после результата — 0,8–1,5 с полной неподвижности, затем подсветка ответа |

Правило математики: **смена вида без потери объекта** — объект не исчезает и не появляется заново, если это тот же объект (морфинг вместо cut). Это и есть «3B1B-ощущение».

### 3(б). Переходы между сценами

| Переход | Длительность | Механика | Когда | Когда нет |
|---|---|---|---|---|
| Hard cut | 0 | на сильную долю/начало фразы | внутри одного смысла, быстрый ритм | после длинной сцены без звука |
| Cut + анимация входа | 0 + 12–18f | новое строится с нуля | смена подтемы | — |
| Match cut (форма/цвет/позиция) | 0–6f | объект A в той же точке и размере становится объектом B (круг-яблоко → круг-ноль) | связать две идеи, «дорогой» эффект | если формы не совпадают ≥ 70 % |
| Morph (shape/формула) | 18–36f | одна форма/формула перетекает в другую | математика, «это превращается в…» | разная топология |
| Shape wipe (круг/плашка/диагональ) | 12–20f, expo-in-out | цветная фигура бренда заполняет кадр, затем открывает новый; 2–3 слоя со stagger 2–3f разных оттенков | смена сегмента, переход к квизу | чаще 1 раза на 15–20 с |
| Mask/iris reveal | 12–18f | круг из точки интереса (из объекта на экране) | «зайдём внутрь», к детали | без мотивированного центра |

| Whip pan | 8–12f, expo-in-out, directional blur 60–150 | быстрый сдвиг кадра на ширину, смаз | «в это время», сравнение «а вот…» | в спокойных объяснениях |
| Slide/push | 15–20f, quart-in-out | новая сцена выталкивает старую | последовательность шагов (шаг 1 → 2) | — |
| Dissolve | 10–20f | crossfade | время/память, мягкая сцена | в коротких роликах почти никогда: выглядит «слайд-шоу» |
| Glitch, 3D-cube, star wipe, page turn | — | — | **не использовать** | признак любителя |

Правила: **один тип перехода на один тип границы** (между словами — push, к квизу — shape wipe, к награде — iris). Переход — 2–4 % длительности ролика суммарно. Выход старой сцены можно начинать на 3–4 кадра до конца фразы, вход новой — совпадает с началом новой фразы.

### 3(в). Линии, коннекторы, аннотации

Правила:
- Линии рисуются **от источника к цели** (от подписи к объекту — нет: от объекта к подписи, чтобы глаз шёл за линией к новой информации).
- **Исчезают обратным trim** (end → start или start догоняет end) за 60–70 % времени появления, ease-in.
- Цвет аннотаций — один акцент для «смотри сюда» на весь эпизод; второй — только для «неверно».
- Trim paths: анимировать **End** 0→100 % для рисования; эффект «бегущего штриха» — End опережает Start на 15–30 % (Start догоняет с задержкой 3–6f).
- Толщина не масштабируется вместе со слоем при зуме камеры — либо компенсировать (stroke × 100/scale), либо принять, но не допускать разной толщины у одинаковых по смыслу линий в одном кадре.

Выражения (полностью детерминированные, без random без seed):
- дыхание: `s = 100 + 3*Math.sin(time*2*Math.PI/2.2 + index); [s, s]`
- покачивание: `3*Math.sin(time*2*Math.PI/2.6 + index*0.7)`
- для «ручного» подрагивания (boil, как у рисованной анимации) — `posterizeTime(8); wiggle(8, 1.5)` с `seedRandom(index, true)` — 8 fps, 1–2 px.

### 3(д). Работа с картинками, особенно ИИ-сгенерированными

**Подача картинки**

| Приём | Параметры |
|---|---|
| Рамка-карточка | скругление 24–40 px (на 1080), обводка 0 или 6–10 px белая, тень как у стикеров; padding внутри 0 |
| Вырезка с обводкой (стикер) | фон удаляется (fal.ai background removal / BiRefNet), затем die-cut обводка 8–14 px + тень; обязательно проверить ореолы — Matte Choker / Simple Choker −1…−2 px, затем обводка |
| Ken Burns | scale 100→108–115 % за 4–8 с (≈ 1,5–2,5 %/с), лёгкий сдвиг 2–4 % кадра к точке интереса; linear или sine-in-out; не больше 120 % (иначе виден пиксель — генерировать с запасом ×1,5 разрешения) |
| Зум к детали | scale камеры 100→180–250 % за 18–30f quart-in-out, к заранее размеченной точке (x,y в долях); с подсветкой детали кругом после остановки |
| Маскированное раскрытие | маска-прямоугольник/круг, feather 0–40 px, раскрытие 15–20f expo-out; «шторка» с цветной полосой-ведущей 8–16 px |
| Параллакс 2.5D | 3 слоя: фон (в fal: inpaint фона после вырезки объекта), средний, передний; камера сдвиг 3–6 % кадра за 4–6 с; скорость слоёв 0,3 / 0,7 / 1,0; ± слегка разные scale; глубина blur дальнего 3–8 px |
| Сравнение | split 50/50 с разделителем 4–6 px; или slider-wipe (разделитель едет 0→50 % за 20f); подписи над половинами; вариант «до/после» — iris |
| Сетка вариантов (квиз) | 2×2 в 9:16, 1×4 или 2×2 в 16:9; одинаковые размеры и рамки, зазор 24–40 px |
| Duotone под палитру | Tint/Colorama/Gradient Map: тени → тёмный цвет бренда, света → светлый; mix 30–60 % для «связки» с серией, 100 % для фоновых картинок |

**Как сделать разнородные ИИ-картинки единообразными** (сначала на этапе генерации, потом в AE):

1. **Генерация:** один «style-prompt» на серию (фиксированный суффикс: стиль, свет, палитра, толщина контура, фон), фиксированная модель и версия, референс-картинки/IP-adapter или LoRA стиля, фиксированный seed для серии одного персонажа. Генерировать объект на однотонном фоне (для вырезки) и отдельно фоны без объектов.
2. **Нормализация в AE (пресет `image.normalize`):**
   - Levels/Auto Levels в узких пределах или Curves: чёрная точка 3–8 %, белая 92–97 %;
   - Hue/Saturation: насыщенность −10…−25 % (ИИ перенасыщает);
   - Color tint к палитре: Tint 10–20 % (map black → тёмный бренд-цвет, white → светлый);
   - лёгкое grain/noise 2–4 % у всех картинок одинаковое — склеивает разные источники;
   - одинаковая обводка/рамка/тень — самый сильный унификатор;
   - одинаковое направление света (тень всегда вниз-вправо) — выбирать при генерации.
3. **Кадрирование по правилам:** главный объект занимает 50–70 % высоты карточки, горизонт и линия глаз персонажа — на одной высоте у соседних карточек.
4. **Проверка артефактов ИИ:** руки/пальцы, текст на картинке (ИИ-буквы — удалять или закрывать), лишние объекты по краям, разные пропорции у одного персонажа. Текст никогда не берётся с картинки — только наш слой.
5. **Разрешение:** генерировать минимум 1,5× от размера показа (для Ken Burns/зума — 2×); для 9:16 полноэкранного фона — 1440×2560 или upscale.

### 3(е). Кинетическая типографика

**Шкала размеров** (модульная шкала ≈ 1,25–1,33; px при короткой стороне 1080):

| Роль | 9:16 (1080×1920) | 16:9 (1920×1080) | Начертание |
|---|---|---|---|
| Hero (одно слово, ответ) | 140–200 | 120–180 | ExtraBold/Black |
| H1 заголовок | 96–120 | 80–100 | Bold |
| H2 / вопрос квиза | 64–80 | 56–72 | Bold/SemiBold |
| Основной текст / пример | 48–60 | 44–52 | Medium/SemiBold |
| Транскрипция | 40–52 (≈ 55 % hero-слова) | 36–48 | Regular (IPA-шрифт) |
| Перевод / подпись | 40–48 | 36–44 | Regular/Medium |
| Минимум для чего угодно | 36 (лучше 40) | 32 | ≥ Medium |

WCAG: «крупный» текст = 18 pt (≈ 24 px) или 14 pt жирный; контраст 4,5:1 для обычного, 3:1 для крупного [И]. Для видео на телефоне с бликами брать **≥ 4,5:1 для всего**, ≥ 7:1 для основного текста.

**Разрядка, интерлиньяж, длина строки:**
- tracking: hero/заголовки капсом +20…+60 (AE tracking в 1/1000 em), заголовки строчными −10…0, основной текст 0…+10, мелкий текст +10…+25;
- leading 110–120 % для заголовков, 125–140 % для текста;
- длина строки в 9:16 — **16–24 символа**, максимум 2–3 строки; в 16:9 — до 40–45 символов, 2 строки;
- не разрывать артикль и слово, предлог и слово; не оставлять одно слово в последней строке.

**Анимация:**

| Пресет | По чему | Механика | Время |
|---|---|---|---|
| `text.rise` (по умолчанию) | слова | Y +30…60 px → 0, opacity 0→100 % за первые 50 %, quint-out | 10–12f/слово, stagger 2–3f |
| `text.mask-up` | строки | текст выезжает снизу из-под маски строки (track matte), Y +100 % кап-высоты | 12–15f, stagger 4f, expo-out |
| `text.pop` | слово-акцент | scale 80→105→100 %, back-out | 10f |
| `text.type` | буквы | печать 1–2f/букву + курсор мигание 0,5 с | для «написания» ответов |
| `text.highlight` | слово в строке | цвет → акцент за 6f или маркер-плашка | синхронно со словом VO |
| `text.counter` | числа | Source Text expression, tabular figures | — |
| `text.out` | блок | opacity + Y −20 px, ease-in, без stagger или 1f | 6–8f |

Правила читаемости на мобильном:
- **Не анимировать текст, пока его читают.** Вход закончен — текст неподвижен до выхода (допустим только highlight текущего слова).
- Stagger по буквам — только для 1–3 коротких слов; для фраз — по словам или строкам.
- Не использовать blur > 10 px, rotation > 10°, 3D-разлёт букв — они разрушают силуэт слова.
- Обводка текста 4–8 px или плашка (opacity 85–100 %, радиус 16–24 px), если под текстом картинка; тень одна на серию (offset 0/4, blur 8–12, 30–40 %).
- Не капслок для предложений (только 1–3 слова); английские слова для изучения — в обычном регистре (так их и запоминают).

**Safe areas**

9:16 (1080×1920), опубликованные платформами отступы для рекламы (органика близка) [И]:

| Платформа | Сверху | Снизу | Слева | Справа |
|---|---|---|---|---|
| YouTube Shorts (Google Ads) | 288 | 672 | 48 | 192 |
| TikTok (In-Feed Ads, шаблон 720×1280 ×1,5) | 240 | 660 | 120 | 120 (+ колонка кнопок 180 px шириной от y = 840) |
| Instagram Reels (Meta, проценты) | ~269 (14 %) | ~672 (35 %) | ~65 (6 %) | ~65 (6 %) |
| **Общая безопасная зона kemel-bilim** | **290** | **680** | **120** | **200** |

Итог: безопасный прямоугольник **x 120…880, y 290…1240** (760×950 px). Критичный текст и ответы квиза — только там. Зона y 1240–1500 — «полубезопасная» (может перекрываться описанием): там можно декоративное и дублирующееся. Ключевой объект — в верхних 2/3 безопасной зоны (центр ≈ y 700–800).

16:9: action safe 93 %, title safe 90 % (SMPTE) — отступы title safe 96 px по бокам и 54 px сверху/снизу для 1920×1080; практично держать текст в 80 % (отступы 192/108 px) и не ставить важное в нижние 12 % (субтитры, прогресс-бар YouTube).

Адаптация 16:9 ↔ 9:16: делать **не кроп, а перекомпоновку**: в 9:16 элементы стекаются вертикально (картинка сверху, слово ниже, перевод ниже), размеры текста ×1,15–1,3 относительно 16:9, сетки 2×2 вместо 1×4.

## 4. Игровые элементы в видео

Цель — **активное припоминание**: зритель должен сам сгенерировать ответ до раскрытия (Pimsleur: «услышь — пауза — ответь — сверь» [И]; retrieval practice эффективнее повторения [И]).

### 4.1 Квиз «выбери вариант»

| Фаза | Время | Визуал | Звук |
|---|---|---|---|
| Анонс | 0,5–0,8 с | бейдж «QUIZ»/«Проверь себя» shape wipe фона квиза (свой цвет режима) | stinger 0,5 с |
| Вопрос | время озвучки + 0,5 с | вопрос сверху (H2), картинка-стимул | VO |
| Варианты | stagger 4f | 2–4 карточки (A/B/C/D), одинаковые, буквы-метки слева или цвет+форма (не только цвет — дальтонизм) | лёгкий pop на каждую |
| Думай | 3–5 с (дети 7–10: 5 с; подростки: 3 с) | таймер (см. 4.2), варианты слегка «дышат» 100↔102 % в фазе со сдвигом | tick 1/с, последние 3 тика выше |
| Подсказка (опц.) | на 50–60 % таймера | неверный вариант гаснет до 40 % | soft pop |
| Раскрытие | 0,4–0,6 с | неверные → 35–50 % opacity + scale 95 %; верный → scale 108→100 %, цвет «верно», галочка рисуется trim 8f, лёгкий конфетти/искры 12–20 частиц ≤ 0,8 с | ding |
| Объяснение | 2–4 с | почему верно: подчёркивание/стрелка к ключу | VO |
| Награда | 0,8–1,2 с | звезда вылетает из верного варианта к счётчику (дуга, 15–21f), счётчик +1 с bump 100→120→100 % | sparkle + coin |

Правила: озвучка всегда говорит «поставь на паузу, если нужно больше времени» в первом квизе ролика; позиция верного ответа меняется между вопросами; ответ никогда не раскрывается раньше конца таймера; не наказывать «неверно» громко — неверные варианты просто гаснут.

### 4.2 Таймер

| Вид | Параметры |
|---|---|
| Кольцо | диаметр 160–220 px (9:16), толщина 14–20 px, трек 20 % opacity, прогресс — trim path end 100→0 % **linear**, round cap; цифра в центре 72–96 px, tabular |
| Полоса | высота 12–20 px, ширина 60–80 % safe-зоны, скругление = половина высоты; linear |
| Цвет | акцент → тёплый/предупреждающий в последние 30 % (плавно за 10f), не красный «тревога» для малышей |
| Последние 3 с | цифра bump 100→115→100 % на каждой секунде (6f), тик выше на тон |
| Конец | кольцо «лопается» (scale 110 % + opacity 0, 6f) → раскрытие |

### 4.3 «Пауза — подумай» / «Повтори вслух»

- Значок паузы/мысли (облачко, «?») появляется back-out 12f, idle-пульс 1,5 с; длительность паузы 2–3 с для произношения, 3–5 с для вопроса.
- Для произношения: визуал «волна» (5–7 столбиков, scale Y 30–100 %, частота 6–8 Гц, затем затухание) показывает «твоя очередь».
- После паузы — эталон: диктор говорит слово, слово подсвечивается по слогам.

### 4.4 Раскрытие ответа: варианты

| Вид | Механика | Когда |
|---|---|---|
| Flip-карточка | rotation Y 0→90° (ease-in 6f), смена контента, 90→0° (ease-out 9f, overshoot −4°) | слово ↔ перевод |
| Scratch/шторка | маска уезжает 15f expo-out с цветной ведущей полосой | картинка-загадка |
| Unblur | blur 40→0 + scale 105→100 за 15–20f | «что на картинке?» |
| Пазл/кусочки | 4–9 тайлов, stagger 2f, каждый flip | награда, итог |
| Заполнение пропуска | плашка «___» → слово выезжает снизу из-под маски 10f, подчёркивание 8f | грамматика, «вставь слово» |

### 4.5 Очки, звёзды, прогресс

- **Счётчик** в одном и том же месте всю серию (9:16: верх safe-зоны, y ≈ 300–380, справа x ≈ 700–860 — НЕ правее 880). Размер иконки 64–80 px, цифра 56–72 px.
- **Прогресс-бар эпизода** (точки шагов 3–5 шт.): показывает сегменты, текущий — заполнен. Даёт ощущение «ещё немного» (segmenting + удержание).
- **Награда в финале:** 1–3 звезды по числу квизов, каждая stagger 6–8f, scale 0→120→100 % + rotation −20→0 + sparkle; общая длительность ≤ 2 с.
- Частота наград: одна маленькая на каждый квиз + одна итоговая. Больше — обесценивается.
- Персонаж-гид реагирует на ответ позой (радость/«ну почти») — без липсинка достаточно смены позы с anticipation 3–4f и overshoot.

## 5. Дизайн-система серии

### 5.1 Палитра

| Роль | Кол-во | Требования |
|---|---|---|
| Фон (светлый) + фон режима (квиз/награда) | 1 + 2 | фоны слабонасыщенные; L* 92–97 светлый |
| Текст (тёмный, почти чёрный с оттенком бренда) | 1 | не #000; контраст с фоном ≥ 7:1 |
| Светлый (белый/кремовый для обводок и текста на тёмном) | 1 | — |
| Основной бренд-цвет | 1 | плашки, переходы, логотип |
| Акцент «смотри сюда» | 1 | максимально отличается по тону от бренд-цвета; ≤ 10 % площади |
| Семантика: верно / неверно | 2 | верно — зелёный, неверно — приглушённый красный/коралловый; всегда с иконкой (✓/✕), не только цвет |
| Цвета частей речи / переменных | 3–4 | средняя насыщенность, все различимы при дальтонизме (проверить симуляцией deuteranopia) |

Пример ориентира: у Duolingo ядро — 4 цвета (Feather Green #58CC02, Mask Green #89E219, Eel #4B4B4B для текста, Snow #FFFFFF как основной фон) плюс вторичные (Macaw #1CB0F6 и др.) [И] — «мало ядра + семантические вторичные».

Правило 60/30/10: 60 % фон, 30 % поддерживающие (карточки, картинки), 10 % акцент. Тень и тёмные детали — оттенок тёмного бренд-цвета, не серый.

### 5.2 Шрифты

- **2 гарнитуры максимум:** дисплейная (заголовки, слова) + текстовая (перевод, подписи); плюс IPA-шрифт для транскрипции, если основной не покрывает IPA.
- Обязательная поддержка: латиница, кириллица, **казахская кириллица (Ә ә, Ғ ғ, Қ қ, Ң ң, Ө ө, Ұ ұ, Ү ү, Һ һ, І і)**, IPA, табличные цифры.
- Кандидаты (Google Fonts, OFL): Nunito / Nunito Sans, Rubik, Montserrat Alternates, Manrope, Inter, Onest, Golos Text, Noto Sans (+ IPA); для «детскости» — округлые (Nunito, Rubik, Comfortaa для заголовков). Перед выбором проверять казахские буквы.
- «Инфантильные» однoэтажные a/g не обязательны: исследования Университета Рединга не показали разницы в скорости чтения детей [И]; важнее крупный x-height, открытые формы и различимость I/l/1, O/0.
- Начертания: Bold/ExtraBold для слов и вопросов, Medium/SemiBold для текста; Light/Thin — нет.

### 5.3 Сетка и раскладка

- **Базовый модуль 8 px** (все отступы кратны 8: 16, 24, 32, 48, 64, 96).
- 9:16: 4 колонки внутри safe-зоны (760 px), gutter 24–32 px; вертикальные «полки»: заголовок (y 290–420), главный объект (y 420–1000), текст/варианты (y 1000–1240).
- 16:9: 12 колонок, поля 192 px (80 % ширины), gutter 32 px; основные компоновки: центр, 50/50, 1/3+2/3.
- Одинаковые элементы — всегда в одних и тех же местах всех эпизодов (счётчик, прогресс, логотип, плашка темы).

### 5.4 Консистентность и структура библиотеки шаблонов

Как организуют студии (Kurzgesagt: соглашения об именах с префиксом группы, напр. `BG_` [И]; MOGRT/Essential Graphics; дизайн-токены):

1. **Токены** (`tokens.json`): цвета, шрифты, размеры шкалы, отступы, радиусы, толщины, тени, длительности, кривые — всё по именам. Пресеты ссылаются на токены, а не на числа. Смена бренда/темы = смена токенов.
2. **Примитивы** (motion presets): `enter.rise`, `exit.fade-down`, `emphasis.pop`, `draw.trim`… — применяются к любому слою.
3. **Компоненты** (MOGRT-аналоги): `wordCard`, `quizChoice4`, `timerRing`, `starCounter`, `callout`, `numberLine` — композиции с параметрами (текст, картинка, цвет-роль, длительность), с внутренней анимацией из примитивов.
4. **Сцены-шаблоны**: `hook`, `wordIntro`, `examplePhrase`, `quiz`, `reveal`, `recap`, `outro` — собираются из компонентов, имеют слоты и длительности, привязанные к таймкодам VO.
5. **Формат-адаптеры**: для каждой сцены раскладка 16:9 и 9:16 отдельно (не масштабирование), общий «смысловой» JSON.
6. **Именование слоёв:** `ROLE_name_index` (`BG_`, `IMG_`, `TXT_`, `UI_`, `FX_`, `CAM_`, `CTRL_`), контроллеры — null `CTRL_scene` со слайдерами (длительность, амплитуда idle, цвет-роль).
7. **Версионирование:** `kit_version` в каждом JSON; эпизоды пинят версию; изменения кита — только обратно совместимые внутри мажорной версии.
8. **Кадр-эталон (style frame)** на каждую сцену — PNG для сверки; авто-проверки: текст в safe-зоне, минимальный кегль, контраст, отсутствие ключей с influence 33,3 %, нет текста, двигающегося во время удержания.

## 6. Типичные ошибки, выдающие любительский моушн

| Ошибка | Как выглядит | Правило-лечение |
|---|---|---|
| Easy Ease по умолчанию / linear | вялое, «пластиковое» или механическое движение | кривые из §1.2, influence 70–90 % на посадке |
| Всё появляется одновременно | шум, глазу некуда смотреть | stagger 2–5f, прогрессивное раскрытие |
| Одинаковое время для всего | монотонно | длительность по размеру и важности (§1.1) |
| Вход и выход одной длины, выход «красивый» | затянутые сцены | выход 60–75 % от входа, ease-in |
| Анимация не связана с голосом | картинка «отстаёт» | старт на 2–4f раньше слова; монтаж под VO |
| Слишком много шрифтов/цветов | «ярмарка» | 2 гарнитуры, палитра §5.1 |
| Текст двигается, пока его читают | невозможно прочитать | вход → неподвижно → выход |
| Текст дублирует речь целиком | redundancy, перегрузка | ключевые слова; полные фразы — только учебный материал |
| Мелкий текст на 9:16, текст под UI платформы | не видно на телефоне | ≥ 40 px, safe-зона x120–880, y290–1240 |
| Пресетные эффекты (glitch, lens flare, star wipe, bevel, drop shadow 45° чёрная 75 %) | «шаблон 2010-х» | переходы §3б, тени §3г |
| Разные стили картинок рядом | коллаж | нормализация §3д, одна рамка/обводка/тень |
| Scale от 0 % для всего | «вылупляется из точки» | от 60–85 % + opacity; 0 % только для стикеров с overshoot |
| Без motion blur на быстрых движениях | стробоскоп | motion blur 180°/−90° на перемещениях > 40 px/кадр f30 |
| Нет пауз | зритель не успевает понять | 0,8–1,5 с неподвижности после ключевого результата |
| Overshoot на всём | «желе» | overshoot только у стикеров/наград, ≤ 3–5 % у текста |
| Idle у всех объектов | мельтешение | idle ≤ 3 объекта, у главного |
| Кроп 16:9 → 9:16 | обрезанные элементы | перекомпоновка |
| Пиксели при зуме ИИ-картинки | мыло | генерация с запасом ×1,5–2 |
| Логотип-заставка 5 с в начале Shorts | уход в первые 3 с | логотип ≤ 1,5 с в конце или ватермарк |
| Разная толщина одинаковых линий, «грязные» концы | неаккуратно | токены толщины, round caps |
| Субпиксельный «дрожащий» текст при медленном движении | мерцание | текст: целые px в конце движения, тексты статичны во время Ken Burns фона |

### 7.11 Сцены и QA-правила

- Сцены: `scene.hook` (≤ 3000, без логотипа), `scene.topic`, `scene.word` (`lang.wordCard`), `scene.example`, `scene.quiz` (`game.*`, ≈ 12000), `scene.recap`, `scene.outro` (stars + CTA, логотип ≤ 1500).
- Ритм-валидация: в каждом окне 4 с есть хотя бы одно событие (вход/акцент/камера); в каждом окне 4–6 с — не больше одного «громкого» события.
- Lint-правила (для `audit_animation`):
  1. нет ключей с influence 33,3 % и speed 0 на обеих сторонах (Easy Ease по умолчанию) — предупреждение;
  2. текст внутри safe-зоны, кегль ≥ min, строк ≤ maxLines, символов в строке ≤ maxCharsPerLine;
  3. контраст текст/фон ≥ 4,5:1 (цель 7:1);
  4. текст не имеет анимированных position/scale в интервале удержания;
  5. время удержания ≥ формулы `text.hold`;
  6. выход короче входа;
  7. картинки: srcScale ≥ 1,5 при Ken Burns/zoom, maxScale ≤ 120 % без запаса;
  8. одновременно idle ≤ 3 слоёв;
  9. суммарный stagger блока ≤ 700 мс.
