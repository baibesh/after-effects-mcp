# Кит After Effects — одна страница вместо кода

Общий кит проектов kemel-bilim и dilyolu (и MCP-сервера в этом репозитории). **Источник — `ae-plugin/kit`**; в проекте `ae/kit/` — копия с меткой `.kit-source` (коммит ae-plugin), ролики пишут `//@include "../../kit/core.jsx"` как раньше, `KB_ROOT` — папка `ae/` проекта.

- Правка кита: в `ae-plugin/kit` → коммит → `node ~/Projects/ae-plugin/tools/kit-sync.mjs <проект>/ae` → контрольные кадры проекта. Копию в проекте не править: синхронизация откажется её затирать и назовёт файлы.
- Сверка без записи: `kit-sync.mjs <проект>/ae --check` (её же зовёт `tools/run.sh` проекта). Синхронизируются и подпапки (`presets/`, `heroes/`, `styles/`, `library/`), файлы `.jsx`, `.md` и `.json`.
- Почему не символическая ссылка: ExtendScript не находит вложенные `//@include` через ссылку (`reels → local/x.jsx → ../kit/project.jsx → core.jsx` — «File or folder does not exist»), AE 26.5. Неудачный `//@include` показывает модальный диалог и вешает все следующие скрипты.

Каталог `kit/*.jsx`: 133 функции (98 рабочих + 35 служебных). Что есть, когда брать, где грабли. Правила кода — ES3, `//@include`, доступ только по matchName, точка входа `kbRun`, глубина цвета эффектов, валидатор — в `../README.md` и здесь не повторяются. Имена и типы параметров эффектов — `tools/data/effect-params-names.json` (снято зондом с живого AE).

## Слои кита

1. **`core.jsx`** — журнал, доступ к свойствам по matchName, одна отмена на запуск. Подключается первым, все остальные файлы тянут его через `//@include`.
2. **Базовые**: `project` (проект 32 бита, композиция 1080×1920, палитра), `motion` (ключи и easing), `text`, `shape`, `footage` (дудлы), `look` (бумага, дрожь линии, зерно), `hero` (живой растровый герой: дыхание, разрез по шее, кивок, сквош, смена поз, тень вырезкой), `space` (2,5D: стена, вырезки, камера с ГРИП, свет с тенями), `fx` (жидкая заливка, конфетти, свечение), `render` (контрольные кадры и превью).
3. **Приёмы витрины `show-*.jsx`** — по блокам ролика `reels/showcase`: **a** эхо, дуги, рывок слова · **b** бумажная вырезка и перевод фокуса · **c** свет (ядро, анаморфный штрих, лучи, лужа света) · **d** морф, жидкость, веер · **e** блик и подгон кегля · **hand** маркер и подчёркивание «как рукой» · **final** рывок панорамы, встряска, хроматическая аберрация. Приёмы других роликов там же: **brick** кирпич-слово, куча и кладка (`reels/say-simple`).
4. **Пресеты движения** — `move.jsx` (одна точка подключения), `presets/tl-*.jsx` (41 движение: текст, акценты, субтитры, плашки, камера, реакции героя), `heroes/` (паспорта героев). Каталог и API — §6.
5. **Стили серии и библиотека** — `style.jsx`, `styles/*.json`, `library/ease.json`: токены оформления (цвет, шрифт, формы, движение) и кривые cubic-bezier с настоящей скоростью на ключах; `library.jsx`, `library/{motion,text,lines}.json`: 30 примитивов, которые берут оформление из стиля. §7.
6. **`probe.jsx`** — зонд: снимает с живого AE то, чего нет в документации, в `tools/data/`. В роликах не участвует, запускается отдельно (`tools/run.sh kit/probe.jsx`).

Зависимости: `show-hand` → `shape` + `look`, `show-b` → `space`, `show-c` → `project`, `show-e` → `text`, `hero` → `core` + `motion`, `audio` → `core` + `footage`, `show-brick` → `space` + `text` + `show-hand` (берёт оттуда `kbHandNoise`, чтобы не заводить третий генератор), `face` → `motion` + `char` (`kbTr`, `kbHT`, `kbHold`, `KB_F`). Приёмы витрины друг друга не знают, порядок подключения — любой.

## Настройки проекта — `ae/kit.config.jsx`

То, чем проекты различаются, вынесено из кита в файл проекта. `core.jsx` выполняет его при подключении (если файла нет — значения по умолчанию). В файле доступен `KB_ROOT`; поля дописываются в `KB_CONFIG`:

```js
// ae/kit.config.jsx — настройки кита для этого проекта
KB_CONFIG.fonts = {black: "InterKB-Black", bold: "InterKB-Bold", regular: "InterKB-Regular"}; // KB_FONT целиком
KB_CONFIG.doodleDirs = [KB_ROOT.parent.fsName + "/studio/public/reels/doodle/"];                // после ae/assets/doodle/
KB_CONFIG.probeFonts = "inter|caveat";                                                          // какие семейства снимает зонд
```

| Поле | По умолчанию | Где действует |
|---|---|---|
| `fonts` | Inter-Black / -Bold / -SemiBold / -Medium / -Regular | `KB_FONT` в `text.jsx` |
| `doodleDirs` | `[]` | `KB_DOODLE_DIRS` в `footage.jsx`: поиск PNG после `ae/assets/doodle/` |
| `probeFonts` | `"inter"` | `kbProbeFonts` в `probe.jsx`: регулярное выражение по семейству |
| `sfxDir` | `"assets/sfx-soft/"` | папка мягких звуков от `ae/` — `TL_S.sfx.dir` в `kbMoveStyleDefaults` (§6); файлы звуков живут в проекте |
| `hero` | нет | герой `kbActor` по умолчанию (id из `heroes/heroes.jsx`: `arlan`, `aidos`) |
| `heroRoot` | папка над `ae/` | откуда считаются пути `files.dir` паспортов героев |

Своё, что нужно только одному проекту (`dilyolu.jsx`), живёт в проекте (`ae/local/`), не в ките.

## 1. Ядро, проект, ключи, кадры

| Функция | Сигнатура | Что делает | Когда брать | Ограничение |
|---|---|---|---|---|
| `kbLog` | `(message)` | строка со временем в `out/ae.log` | отладка, отчёт шага сборки | файл только дописывается, UTF-8 / Unix |
| `kbProp` | `(owner, path[]) → Property` | свойство по цепочке matchName | любой доступ к значению и ключам | имя звена, которого нет, попадает в ошибку, но верного не подсказывает |
| `kbGroup` | `(owner, path[]) → PropertyGroup` | то же для группы | когда в группу будут добавлять | тот же `kbResolve` внутри, разница только в типе для валидатора |
| `kbAdd` | `(group, matchName) → PropertyGroup` | эффект, аниматор текста, содержимое shape-слоя | всё, что добавляется в группу | падает, если `canAddProperty` false — проверять состав группы зондом |
| `kbEffect` | `(layer, matchName) → PropertyGroup` | эффект на слой (`ADBE Effect Parade`) | всегда вместо ручного пути | порядок эффектов = порядок вызовов, переставить нечем |
| `kbRun` | `(name, build) → string` | одна отмена на запуск, ошибка с файлом и строкой в журнал | точка входа каждого `build*.jsx` | исключение **не пробрасывается**: возвращается строкой `ERR …`, проверять вывод |
| `kbNewProject` | `()` | новый проект: 32 бита, линейное смешивание | первым делом в сборке | закрывает открытый проект **без сохранения** |
| `kbComp` | `(name, seconds) → CompItem` | композиция 1080×1920 / 30 fps, фон `paper`, motion blur 270° / −135°, 32 сэмпла | каждая сцена и общая композиция | размер и fps — из `KB_FRAME`, параметром не меняются |
| `kbFill` | `(comp, color, name) → AVLayer` | заливка на весь кадр | подложка сцены | на всю длительность композиции |
| `kbPlace` | `(master, scene, start) → AVLayer` | сцену-прекомпозицию в общую композицию с началом в секунду | сборка ролика из сцен | слой живёт со `startTime`, обрезку задавать отдельно |
| `kbSaveProject` | `(relativePath)` | `.aep` по пути от `ae/` | конец сборки | ручные правки в `.aep` пересборка затирает |
| `kbKeys` | `(prop, times[], values[], ease)` | ключи и одинаковый easing между ними | вся анимация кита | число измерений easing берётся из типа свойства; повторный вызов на тех же временах **переопределяет** easing (этим пользуется `kbArcs`) |
| `kbOvershoot` | `(prop, start, duration, from, over, to)` | перелёт и посадка, ключ перелёта на 0,6 длительности | упругий приход на место | easing зашит `KB_EASE.snap` |
| `kbSaveFrames` | `(comp, times[], prefix)` | PNG в `out/frames/` | смотреть результат без рендера | `saveFrameToPng` пишет **асинхронно** и в 32 битах делит яркость на 10 |
| `kbRenderPreview` | `(comp, relativePath)` | mp4 через очередь (H.264, 15 Мбит/с) | превью сцены или ролика | чистит всю очередь рендера и блокирует AE до конца; звук шаблон пишет сам (Output Audio = Auto → AAC 48 кГц стерео), включать его отдельно не нужно |

**Константы:** `KB_COLOR` (paper, ink, inkSoft, ochre, blue, plum, grey, marker, **markerInk**, coral, teal, **tealInk**) — две последние это поправка для слоя в режиме умножения: в линейном свете `#F5C84B` выходит горчичным. `KB_FRAME` = 1080×1920, 30 fps, safeTop 200, safeBottom 320. `KB_EASE` = `snap` {out 20, into 90} · `soft` {60, 60} · `punch` {10, 95}. `KB_FONT` — из настроек проекта `KB_CONFIG.fonts` (PostScript-имена из `tools/data/fonts.json` проекта), см. «Настройки проекта».

### Живой растровый герой — `hero.jsx`

Оживление дудла без рига. Всё рассчитано на то, что поза лежит **непрозрачным** слоем поверх белого листа: растровые позы идут без альфы, а разрез масками, CC Bend It, Bezier Warp и трек-мат вырезают из слоя прозрачность — под ней должен быть лист, иначе она уйдёт в тень прямоугольником. Образец сборки — `reels/hero-lab/scene-hero.jsx`.

## 4. Что брать вместо чего

- **`kbHandMarker` / `kbHandUnderline` вместо `kbMarkerStroke` / `kbUnderline`.** Ручной вариант владелец принял 18.09: ровная полоса с косыми срезами, но с живым ходом, нибблеными краями и неровной плотностью краски. Старые печатно-ровные функции оставлены для `reels/bes-soz` (scene1, 2, 3, 5) и в новых сценах не берутся. Волны и кляксы владелец отверг — в ручной вариант их не возвращать.
- **`kbLightSweep` только с `opts.target` и `reception: 2`.** Без `target` создаётся корректирующий слой: на бумаге 0,957 любой добавленный свет упирается в белое, и полоса идёт через весь кадр дешёвым вайпом — по кадрам проверено, владелец не принял. Корректирующий слой годится только для тёмных сцен. `target` — сам логотип или прекомпозиция «слово + маркер»: свет считается по её альфе, бумаги не касается.
- **Ореол — на слое источника, а не `kbGlow` на весь кадр.** В тёмной сцене общий порог ловит всё, что лучи подняли выше 1.0 у краёв букв, и первым переходит красный канал — вокруг слова загорается красная кайма. Брать `opts.glow` у `kbOrb` (свой слой, ореол видит только шар). На бумажной сцене `kbGlow` не ставится вовсе.
- **Волокно листов — набор `kbHolePlane`, а не `kbWall`.** У листа: Contrast 4, Brightness 46, Complexity 1 (одна октава), Scale снаружи пропорционально расстоянию до камеры — размах 94–98 % без срезов, в расфокусе зерно гаснет. У `kbWall`, `kbPaperGrain` и ветки `paper` в `kbLiquidFill` остался старый набор Contrast 14 / Brightness 47 / Scale 3,5 / Complexity 4: верх шума упирается в 100 % и даёт белёсые кляксы, а низкая частота переживает блюр и читается пятнами «мокрой бумаги». **Долг кита:** перенести набор листа на все бумажные слои.
- **Вырезание светом — `kbCutByLight` (трек-мат), не `ADBE Set Matte`:** там слой-источник задаётся номером, и на живом AE 2026 берётся не тот слой — слово пропадает целиком, без ошибки в журнале.
- **Тень героя-дудла берёт `kbPaperCutout`, а не сам слой героя.** У слоя позы альфа — прямоугольник листа, тень от него была бы прямоугольником. Двойник с альфой по туши делает обе работы разом: кладёт тень и закрывает героя от неё (слой героя идёт умножением, его белая бумага для тени прозрачна, и собственная тень читалась бы по лицу вторым лицом).
- **Нутро контуров в тени закрывают заливки в отдельной «теневой» композиции, а не морфология.** Замкнуть лицо внутри головы через `ADBE Minimax` («Maximum Then Minimum» и раздельные Maximum + Minimum по альфе, вертикально, радиус 130) и через `ADBE Simple Choker` не выходит: просвет головы ~255 px, а просвет между ног 46–113 px — любой радиус закрывает либо оба, либо ни одного, проверено кадрами. Рабочий приём: та же композиция позы плюс два чёрных эллипса (голова и корпус) сверху, и она подставляется двойнику через `source`. Заливка должна быть **чёрной**: охра дала бы альфу 0,77 и тень просвечивала бы сквозь подложку на четверть.
- **Дудлы в `../studio/public/reels/doodle/` — часто JPEG с расширением `.png`** (`base.png`, `aha.png`, `thinking.png`; в `ae/assets/doodle/` лежат настоящие PNG). Перед копированием в ролик проверять `file <путь>` — иначе AE либо не импортирует, либо тянет джипеговые артефакты по краю туши.
- **Лицо говорящего — `face.jsx`, а не `sbLid`/`sbMouth` из `reels/a2-01-hook` и не растровые накладки.** Эллипс по огибающей и генерация частей лица (Qwen, 14.10) дали брак; векторный рот по формам Rhubarb садится линией той же толщины и цвета, что контур позы. Стопкадры — `reels/face-lab`, ждут утверждения владельца.
- **Кант листа — отдельный shape-слой, не эффект Stroke по маске:** Stroke считается в 8 битах и квантовал бы бумагу с волокном в полтора десятка ступеней.

**Почему имена `tl…` остались.** Файлы перенесены как есть (решение исполнителя при переносе): переименование ~10 тыс. строк `tl→kb` ломало бы побайтную сверку регресса потоков 1–7 и плодило бы второе имя для каждой функции. Публичный API — с префиксом `kb` (таблица ниже), `tl…` — внутренности пресетов. Новые пресеты — в `presets/` с префиксом `tl`, публичная обёртка — в `move.jsx`.

**Порядок подключения.** `tl-ease → tl-move → tl-accent → tl-hand → tl-type → tl-voice → tl-mark → tl-caption → tl-plate → tl-camera → tl-actor → tl-style`, затем `heroes.measured → heroes`. Проще всего — `//@include "../../kit/move.jsx"` одной строкой. Можно подключать файлы по отдельности (как регресс потоков), но не раньше их зависимостей.

**Guard реестра.** `tl-accent.jsx` и `tl-hand.jsx` сами подключают `tl-move.jsx`, и раньше повторный `//@include` обнулял `TL_MOVES` (stream3 §3.3). Теперь в пределах **одного запуска** реестр и текущий стиль сохраняются. Глобальные переменные AE живут между запусками `DoScriptFile` (движок `main` — проверено), поэтому простое «не трогать, если уже есть» протащило бы реестр и стиль прошлого скрипта. Признак «тот же запуск» — объект функции `kbMove`: `//@include` склеивает всё в один текст, объявление поднимается до выполнения и одно на весь запуск, в следующем запуске это новый объект. Остальные таблицы (`TL_FADES`, `TL_ACTORS`, `TLP_METRICS`) по-прежнему сбрасываются при подключении: в них ключи по id композиций, и между запусками им жить нельзя.

### API

| Функция | Сигнатура | Что делает |
|---|---|---|
| `kbMove` | `(layer, name, opts?) → {name, from, start, hit, end, units, sfx[]}` | применить движение; подмена по стилю → множители → `TL_MOVES[name].plan/run` → маркер `sfx:<вид>@<сила>` на кадр удара → строка журнала `MOVE …`. `sfx[]` — все метки движения (раннера и те, что ставит сам пресет: тики `cascade`, плашки, маркер), `{kind, t, strength, layer}`; каждая метка — в `TL_SFX_LOG` и с источником `kb-sfx-src`. `at` — секунды удара (движение приходит на `lead` кадров раньше), `start` — первый кадр; время брать из `kbS/kbAt/kbOn`, не литералом |
| `kbMovePlan` | `(layer, name, opts?)` | то же без ключей — только времена (`PLAN …`) |
| `kbSlot` | `(layer, {in, loop?, out?, at, until, inOpts?, loopOpts?, outOpts?}) → {in, loop, out}` | слоты слоя: вход к `at`, цикл между концом входа и началом выхода, выход к `until`; `outPoint` = конец выхода; без `out` — `WARN no-out` |
| `kbMoveStyle` | `(style)` | включить стиль: объект `KB_STYLE` (как в `style.jsx` ролика) или имя; множители и подмены — из `TL_STYLES`, если в объекте пусты |
| `kbMoveStyleUse` | `(name?, over?) → TL_S` | стиль по имени **с умолчаниями кита** (палитра, шрифты, мягкие звуки) — вместо копирования `style.jsx` |
| `kbMoveStyleDefaults` | `(name?, over?) → KB_STYLE` | тот же объект без включения (дописать поля и отдать в `kbMoveStyle`) |
| `kbSfxDropLayer` | `(layer) → [{kind, t, strength}]` | снять метки `sfx:` композиции, поставленные движениями этого слоя; звать до `layer.remove()` (MCP `delete_layer` зовёт сам). Источник метки — параметр маркера `kb-sfx-src` (id слоев через «\|», по одному на метку комментария); метки без источника (старые, ручные) не трогает |
| `kbSfxFromMarkers` | `(comp, cfg)` | один раз после сборки: по маркерам `sfx:` (и во вложенных композициях) кладёт звуки из `cfg.dir + map[вид].file`, уровень `level − 6 дБ × (1 − сила)`; `cfg` = `TL_S.sfx` |
| `kbPlate` | `(comp, {kind, text|lines, x, y, side?, anchor?, tilt?, seed?, name?}) → {root, body, edge, shadow, text[], …}` | плашка-предмет: `tag`, `slot`, `badge`, `callout`, `card`, `bare`; движения `plate-in` … получают её в `opts.plate` |
| `kbActor` | `(comp, {hero?, feet: [x, y], h, pose?, name?}) → actor` | герой из паспорта; `hero` — id (`"arlan"`) или паспорт, без него — `KB_CONFIG.hero` проекта, иначе Арлан (`KB_HERO_DEFAULT`). Реакции — `kbMove(actor.layer, "take", {…})` |
| `kbActorDone` | `(actor)` | записать каналы актёра (ключи, выражения) — **после всех** реакций |
| `kbHero` / `kbHeroIds` | `(hero?) → паспорт` / `() → string[]` | паспорт по id с проверкой / какие герои есть |
| `kbMoveList` | `({group?, style?}) → []` | каталог из реестра (его отдаёт MCP `list_motions`) |

```js
//@include "../../kit/move.jsx"
kbRun("demo", function () {
  kbNewProject();
  var comp = kbComp("Demo", 4);
  kbFill(comp, KB_COLOR.paper, "paper");
  kbMoveStyleUse("hand");                                   // или kbMoveStyle(KB_STYLE) из style.jsx ролика
  var word = kbText(comp, { text: "BIGGER", font: KB_FONT.black, size: 200, color: KB_COLOR.ink, x: 540, y: 800 });
  kbSlot(word, { "in": "land", loop: "hold-alive", out: "sink-out", at: 1.0, until: 3.2 });
  kbMove(word, "marker-swipe", { at: 1.8 });
  var hero = kbActor(comp, { feet: [540, 1700], h: 600 });  // герой проекта (KB_CONFIG.hero) или Арлан
  kbMove(hero.layer, "nod", { cause: 30 });                 // у реакций cause/start/t0/t1 — кадры, at — секунды
  kbActorDone(hero);
  kbSfxFromMarkers(comp, TL_S.sfx);
});
```

### Как сменить героя

- **По умолчанию — Арлан** (`KB_HERO_DEFAULT = "arlan"` в `heroes/heroes.jsx`): `kbActor` без `hero` и без `KB_CONFIG.hero` берёт его. Позы — PNG 1024² с альфой из `<heroRoot>/ae/assets/heroes/arlan/` (в kemel-bilim — копия `design/mascot-tazy/library/arlan`).
- **На весь проект:** `KB_CONFIG.hero = "aidos";` в `ae/kit.config.jsx` — `kbActor` без `hero` берёт его.
- **Нет позы под роль — запасной путь, не падение.** Если у героя нет роли (или её позы), а у паспорта есть `fallback: {роль: роль|поза}`, актёр берёт запасную позу (цепочка до 4 шагов, в конце — `idle`) и пишет в журнал один раз на роль `WARN ROLE <герой> <роль>: своей позы нет — запасной путь паспорта … = <поза>`. У Арлана сейчас: `doubt → shrug` (тэйк-сомнение), `release → point-side` (доводка броска). Паспорт без `fallback` (Айдос) по-прежнему падает с именем поля. Чего не хватает Арлану — `kemel-bilim-content/design/mascot-tazy/AE-POSES-TODO.md`.
- **Якоря Арлана** (замер `measure-hero.py --hero arlan`): голова `head.c/r/crown`, глаза `head.eyes`, нос `head.nose`, шея `neck.y` (кант худи под наушниками; разрез выключен `rig.split: false` до «ок» владельца — кивок и наклон идут изгибом корпуса, `INFO nod→bend`), ладони `palm/palmEnd` (talk, talk3q, hold-both, hold — кулак), `tip` (point-side, point-down, aha), `hand` (wave, surprised, think≈), `hands` (happy), `palms` (shrug). Роли: `hold → hold-both` (открытая ладонь под ловлю и бросок), `point → point-side | point-down` (`lean-to` берёт ближнюю по углу).
- **В одном вызове:** `kbActor(comp, { hero: "aidos", feet: [540, 1700], h: 600 })` (или сам паспорт `TL_HEROES.arlan`).
- **Новый герой:** паспорт в `heroes/heroes.jsx` по образцу `arlan` (файлы поз `files.prefix` + `files.dir`, `render` doodle | char, лист `sheet`, `ground`/`top`/`axis`, `bend`, `neck` — `null`, если разреза нет, `poses` с якорями `tip`/`palm`/`hand`, `roles` → позы, `calib.bendK`); `null`-поля дописывает замер (`heroes.measured.jsx`, в kemel-bilim — `type-lab-15/stream7/measure-hero.py`; новый замер копируется в `ae-plugin/kit/heroes/` и раздаётся `kit-sync`). Пути `files.dir` — от `KB_CONFIG.heroRoot` (по умолчанию папка над `ae/`).
- Числа героя в код пресетов не попадают (проверка `dupnames7.py --herolit` в kemel-bilim: `HEROLIT 0`); всё, что отличает героя, — в паспорте.

### Через MCP

`list_motions` (каталог; `style` — подмены), `apply_motion` (на слой или `selection: true`, ответ — план start/hit/end), `set_motion_style` (стиль композиции или проекта), `get_selection`; `apply_preset` с `"move:<имя>"` идёт туда же. ## 7. Стили серии и кривые — `style.jsx`, `styles/`, `library/`

Дизайн-система ролика данными: блоки урока (дальше по `docs/spec/lesson-system.md`) не содержат цветов, шрифтов и длительностей — берут токены стиля. Не путать со стилями движения `TL_STYLES` (§6): те меняют характер пресетов движения, эти — всё оформление.

- `styles/_base.json` — база: сетка 8, safe-зоны 9:16/16:9/1:1, шкала текста по форматам, линии, скругления, `motion.dur` (мс), каскады, удержание текста, ритм. Числа — `docs/research/motion-design-pro.md` §7.
- `styles/editorial-dark.json` (A), `swiss-light.json` (B), `color-blocks.json` (C) — переопределяют только своё. Стиль проекта — `ae/styles/<id>.json`, ищется раньше кита.
- `"extends"`: `"_base"` или список `["swiss-light", {"motion": "color-blocks"}]` — объект берёт из стиля только названные группы. Слияние глубокое, списки заменяются целиком. Итог несёт `from` — порядок источников.
- `library/ease.json` — кривые по имени: `bezier` [x1, y1, x2, y2] как в CSS; `keys` — перелёт ключами [доля времени, доля пути] с `segEase` к первому и `settle` между остальными.

| Функция | Что |
|---|---|
| `kbStyle(id)` | итоговый стиль (extends развёрнуты) |
| `kbTok(style, "color.accent")` | токен по пути; ошибка называет, что есть на этом уровне |
| `kbMs(style, "text" \| 450)` | длительность в мс × `motion.tempo` |
| `kbMsToTime(ms, fps)` | секунды на целом кадре |
| `kbHex("#RRGGBB")` | цвет AE 0…1 |
| `kbKeysCurve(prop, start, dur, from, to, "expoOut", amp)` | ключи по кривой; `amp` — доля перелёта (`motion.overshoot`), 0 — без него |
| `kbCurveSegment(bezier, delta, dur)` | speed и influence отрезка: inflOut = x1·100, speedOut = y1/x1·vAvg, inflIn = (1−x2)·100, speedIn = (1−y2)/(1−x2)·vAvg |

Проверено в AE 26.5: значения между ключами совпадают с cubic-bezier до 0,01 % размаха — для убывающих значений (скорость со знаком), позиции по диагонали (скорость — длина хорды) и масштаба по осям; `backOut` даёт пик ровно 112 %.

Чистые функции (`kbStyleResolve`, `kbStyleMerge`, `kbTok`, `kbMs`, `kbCurveSegment`, `kbCurvePoints`) выполняет и сервер MCP (`src/styles.ts`, песочница vm) — один код для `list_styles`/`get_style` и для AE. Тесты без AE: `npm test`.

### Библиотека примитивов — `library.jsx`, `library/{motion,text,lines}.json`

Примитив — данные: длительность (мс или токен `motion.dur`), кривая (`@enter`, `@exit`, `@emphasis`, `@draw` → `motion.ease` стиля, или имя из ease.json), значения от текущего (`"base"`, `{"offset"}` в px при базе 1080, `{"factor"}` в %), параметры `$имя`. Каталог с описаниями — `list_library` или сами файлы.

| Папка | Примитивы |
|---|---|
| `motion` | `enter.rise/slideIn/scaleIn/pop/unblur`, `exit.fadeDown/shrink`, `emphasis.pop/shake/dimOthers/undim`, `idle.breathe/sway/float` |
| `text` | `text.maskUp/letters/rise/fadeWords/unblur/maskDown/highlightWord/counter` |
| `lines` | `draw.underline/marker/circle/strike/arrow/connector`, `callout`, `undraw` |

```js
//@include "../kit/library.jsx"
var st = kbStyle("editorial-dark");
var r = kbLib(st, st.motion.word, word, {start: 0.6});          // r.end — когда закончилось
kbLib(st, "draw.underline", word, {start: r.end - 0.1});
kbLib(st, "draw.arrow", null, {comp: comp, from: tr, to: card, start: 2.1, params: {bend: 0.25}});
kbLib(st, "emphasis.dimOthers", null, {start: 4, others: [label, tr]});
var hold = kbTextHold(st, "I eat an apple every day");          // мс удержания после входа
```

- **Текст** — Expression Selector: у каждой единицы (буквы без пробелов, слова, строки) своя кривая со сдвигом stagger; каскад не дольше `motion.stagger.maxTotal`. Перелёт `backOut` — отрицательный amount, выражение считает кривую так же, как ключи (проверено тестом против cubic-bezier).
- **Маски строк** (`mask: true`): по маске на строку, буквы выезжают из-под своей линии. В многострочном тексте полосы соседствуют, поэтому второй аниматор (`… · hide`) растворяет букву дальше ~0,3 em от её строки; однострочный текст — чистая маска.
- **Линии** — shape-слои в координатах композиции, trim по `@draw`, концы `shape.cap` стиля. Рамка цели — `sourceRectAtTime` с позицией, якорем и масштабом слоя (родитель и поворот не учитываются); подчёркивание — от базовой линии последней строки. `undraw` стирает trim за 65 % прорисовки и сжимает наконечник и точку.
- **Грабли ExtendScript:** `parseFloat("1.1em")` даёт NaN (читается как экспонента `1.1e…`) — длины в em разбираются через `Number(v.replace(/em$/, ""))`.

Демо в трёх стилях: `test/lib-demo.jsx` (сцена «новое слово», композиции `lib · <стиль>`), запуск в открытом тестовом проекте.
